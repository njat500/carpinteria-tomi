Quiero crear una aplicación para **presupuestar proyectos de carpintería y calcular materiales necesarios**, con una interfaz sencilla, visual y fácil de usar.

## PRIORIDAD PRINCIPAL

La aplicación debe tener como **primera opción y pantalla principal** un apartado para **cargar proyectos/plano**, con dos formas de ingreso:

1. **Subir un archivo**
   - Permitir archivos de distintos formatos: PDF, JPG, PNG, WEBP, DWG, DXF, Excel, Word y otros formatos habituales.
   - El sistema debe analizar el archivo cuando sea posible y extraer las medidas, cantidades y especificaciones del proyecto.
   - Si el archivo no puede interpretarse automáticamente, permitir al usuario introducir los datos manualmente.

2. **Cámara**
   - Incluir un botón de cámara claramente visible.
   - Permitir sacar una fotografía directamente desde el celular a planos, dibujos, croquis o medidas escritas a mano.
   - La aplicación debe utilizar OCR/visión artificial para intentar detectar automáticamente las medidas y textos del plano.
   - El usuario debe poder revisar y corregir las medidas detectadas antes de utilizarlas para calcular materiales.

# 1. CÁLCULO DE PLACAS

La función principal debe calcular cuántas placas de madera/material en placa son necesarias para realizar el proyecto.

La medida estándar inicial de una placa será:

**2,60 m × 1,83 m**

Área de una placa:

**2,60 × 1,83 = 4,758 m²**

IMPORTANTE: trabajar siempre con **4,758 m² por placa**, no 47,580 m².

El sistema debe:

- Permitir introducir las medidas de cada pieza.
- Calcular automáticamente el área de cada pieza.
- Sumar el área total.
- Dividir el área total entre 4,758 m².
- Mostrar la cantidad teórica de placas necesarias.
- Redondear siempre hacia arriba para obtener la cantidad mínima de placas completas.

Ejemplo:

Proyecto:
- Pieza A: 2,00 × 0,60 m
- Pieza B: 1,50 × 0,40 m
- Pieza C: 0,80 × 0,50 m

La aplicación debe calcular automáticamente el área de cada pieza y el total.

---

# 2. DESPERDICIO Y OPTIMIZACIÓN DE CORTES

No quiero que la aplicación se limite a dividir el área total por el área de una placa.

Debe contemplar que en carpintería **la distribución de las piezas sobre las placas genera desperdicio**, incluso cuando el área matemática alcanza.

Por eso debe existir un sistema de optimización de cortes.

El usuario debe poder configurar:

- Ancho de la placa.
- Largo de la placa.
- Espesor de la placa.
- Ancho del corte de la sierra (kerf).
- Margen de seguridad.
- Porcentaje de desperdicio estimado, si se desea utilizar una estimación rápida.

El sistema debe intentar distribuir las piezas dentro de las placas disponibles buscando reducir el desperdicio.

Debe considerar:

- Rotación de las piezas cuando sea posible.
- Orientación de la veta cuando corresponda.
- Espesor del corte de la sierra.
- Márgenes.
- Piezas que no entran por sus dimensiones.
- Aprovechamiento de sobrantes.
- Cantidad de placas completas necesarias.

Mostrar dos resultados:

**Cálculo teórico por superficie**
- Área total.
- Área por placa.
- Cantidad matemática de placas.

**Cálculo real de corte**
- Cantidad de placas necesarias.
- Área utilizada.
- Área desperdiciada.
- Porcentaje de desperdicio.
- Sobrantes aprovechables.

Si existe una diferencia entre ambos resultados, explicar claramente por qué.

# 4. CÁLCULO DE CANTOS

La aplicación debe calcular automáticamente los **metros lineales de canto necesarios**.

Cada pieza debe permitir seleccionar qué lados llevan canto:

- Largo 1.
- Largo 2.
- Ancho 1.
- Ancho 2.

También debe existir una opción para seleccionar:

- 1 lado.
- 2 lados.
- 3 lados.
- 4 lados.

La aplicación debe sumar todos los metros de canto necesarios.

Ejemplo:

Una pieza de 1,20 × 0,60 m con canto en los 4 lados:

1,20 + 1,20 + 0,60 + 0,60 = **3,60 metros de canto**

Si hay 5 piezas iguales:

3,60 × 5 = **18 metros de canto**

Mostrar:

**Canto total requerido: 18 m**

Agregar además un porcentaje de margen configurable para compensar desperdicio durante el canteado.

Ejemplo:

18 m + 10 % = **19,8 m recomendados**

# 13. VALIDACIONES IMPORTANTES

La aplicación debe advertir cuando:

- Una pieza supera el tamaño de la placa.
- Una pieza no puede acomodarse respetando la orientación de la veta.
- El proyecto necesita más placas de las calculadas inicialmente por superficie debido al desperdicio.
- Faltan medidas.
- Hay medidas ambiguas detectadas en un plano.
- El usuario intenta calcular sin haber seleccionado material.
- El ancho/largo de placa es incorrecto.
- El kerf es mayor que el margen disponible.

Nunca ocultar errores de cálculo.

# REQUISITO FUNDAMENTAL

La aplicación debe diferenciar claramente entre:

**"Cantidad de placas por superficie"**

y

**"Cantidad de placas necesarias según el despiece y los cortes reales".**

Por ejemplo, si el área total de las piezas es 8 m²:

8 ÷ 4,758 = 1,68 placas

La aplicación puede mostrar:

**Superficie matemática: 1,68 placas**

pero si las piezas no pueden distribuirse correctamente en una sola placa y requieren dos placas:

**Placas reales necesarias: 2**

La cantidad final para comprar debe basarse en el **despiece y la optimización de cortes**, no únicamente en la división de superficies.

El objetivo de la aplicación es que un carpintero pueda pasar de:

**PLANO → DESPIECE → PLACAS → CANTOS → DESPERDICIO → COSTOS → PRESUPUESTO FINAL**

con la menor cantidad posible de trabajo manual.
